# 调试日志记录阶段

## 概览

一个请求在处理过程中会经历多个转换阶段，每个阶段的输入/输出都可以被独立记录。通过 `.env` 中的开关控制各阶段是否启用。

### 日志目录结构

```
data/debug-log/
├── openai_anthropic/          # M0: OpenAI → Anthropic
│   └── {dd}/{hh}/{mm}/{ss}/{id}/
│       ├── input              # OpenAI 格式请求 + 请求头
│       └── output             # 转换后的 Anthropic 格式请求
├── anthropic_kiro/            # M1: Anthropic → Kiro
│   └── {dd}/{hh}/{mm}/{ss}/{id}/
│       ├── input              # Anthropic 格式请求 + 请求头
│       ├── output             # 转换后的 Kiro 格式请求
│       └── kiro_request       # 发送给 Kiro API 的原始 HTTP 请求体
└── kiro_anthropic/            # M2: Kiro → Anthropic
    └── {dd}/{hh}/{mm}/{ss}/{id}/
        ├── input              # Kiro 返回的事件摘要列表
        ├── output             # 转换后的 Anthropic 格式响应/事件
        └── kiro_event_XXXX_*  # 每个 Kiro 事件的原始数据（逐帧记录）
```

- `dd` — 日期（01-31）
- `hh` — 小时（00-23）
- `mm` — 分钟（00-59）
- `ss` — 秒（00-59）
- `id` — 12 位请求唯一编号（UUID 前 12 位）

## 路径 A：Anthropic 兼容端点 (`POST /v1/messages`)

客户端直接以 Anthropic 格式发送请求，不经过 OpenAI 转换。

```
客户端 (Anthropic 格式)
    │
    ▼
┌─────────────────────────────────────────────┐
│  M1: Anthropic → Kiro                       │  ← DEBUG_LOG_MIDDLEWARE_1
│  目录: anthropic_kiro/{dd}/{hh}/{mm}/{ss}/{id}/
│  ├── input   (Anthropic MessagesRequest + headers)
│  ├── output  (Kiro 格式 dict)
│  └── kiro_request (发送给 Kiro API 的完整请求体)
└─────────────────────────────────────────────┘
    │
    ▼
  Kiro API (AWS Event Stream)
    │
    ▼
┌─────────────────────────────────────────────┐
│  M2: Kiro → Anthropic                       │  ← DEBUG_LOG_MIDDLEWARE_2
│  目录: kiro_anthropic/{dd}/{hh}/{mm}/{ss}/{id}/
│  ├── kiro_event_0000_assistantResponseEvent  (逐帧)
│  ├── kiro_event_0001_toolUseEvent            (逐帧)
│  ├── kiro_event_XXXX_*                       (逐帧)
│  ├── input   (所有 Kiro 事件的摘要列表)
│  └── output  (转换后的 Anthropic SSE 事件列表 / 非流式 JSON)
└─────────────────────────────────────────────┘
    │
    ▼
  返回给客户端 (Anthropic SSE / JSON)
```

**记录阶段：2 个（M1 + M2）**

| 阶段 | 开关 | input 文件内容 | output 文件内容 |
|------|------|---------------|----------------|
| M1 | `DEBUG_LOG_MIDDLEWARE_1` | `{headers, body: MessagesRequest}` | `{body: Kiro 格式 dict}` |
| M2 | `DEBUG_LOG_MIDDLEWARE_2` | Kiro 事件摘要 `[{type, index}, ...]` | Anthropic SSE 事件列表 / 非流式响应 JSON |

附加文件：
- `anthropic_kiro/{...}/kiro_request` — 发送给 Kiro API 的完整请求体（M1 或 M2 开启时记录）
- `kiro_anthropic/{...}/kiro_event_XXXX_*` — 每个 Kiro 事件帧的原始数据（M2 开启时记录）

## 路径 B：OpenAI 兼容端点 (`POST /v1/chat/completions`)

客户端以 OpenAI 格式发送请求，需先转为 Anthropic 格式。

```
客户端 (OpenAI 格式)
    │
    ▼
┌─────────────────────────────────────────────┐
│  M0: OpenAI → Anthropic                     │  ← DEBUG_LOG_MIDDLEWARE_0
│  目录: openai_anthropic/{dd}/{hh}/{mm}/{ss}/{id}/
│  ├── input   (OpenAI ChatCompletionRequest + headers)
│  └── output  (转换后的 Anthropic MessagesRequest)
└─────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────┐
│  M1: Anthropic → Kiro                       │  ← DEBUG_LOG_MIDDLEWARE_1
│  目录: anthropic_kiro/{dd}/{hh}/{mm}/{ss}/{id}/
│  ├── input   (Anthropic MessagesRequest + headers)
│  ├── output  (Kiro 格式 dict)
│  └── kiro_request (发送给 Kiro API 的完整请求体)
└─────────────────────────────────────────────┘
    │
    ▼
  Kiro API (AWS Event Stream)
    │
    ▼
┌─────────────────────────────────────────────┐
│  M2: Kiro → Anthropic                       │  ← DEBUG_LOG_MIDDLEWARE_2
│  目录: kiro_anthropic/{dd}/{hh}/{mm}/{ss}/{id}/
│  ├── kiro_event_0000_*                       (逐帧)
│  ├── kiro_event_XXXX_*                       (逐帧)
│  ├── input   (所有 Kiro 事件的摘要列表)
│  └── output  (Anthropic SSE 事件列表 / 非流式响应)
└─────────────────────────────────────────────┘
    │
    ▼
  OpenAI 格式转换（代码内转换，不单独记录）
    │
    ▼
  返回给客户端 (OpenAI SSE / JSON)
```

**记录阶段：3 个（M0 + M1 + M2）**

| 阶段 | 开关 | input 文件内容 | output 文件内容 |
|------|------|---------------|----------------|
| M0 | `DEBUG_LOG_MIDDLEWARE_0` | `{headers, body: ChatCompletionRequest}` | `{body: MessagesRequest}` |
| M1 | `DEBUG_LOG_MIDDLEWARE_1` | `{headers, body: MessagesRequest}` | `{body: Kiro 格式 dict}` |
| M2 | `DEBUG_LOG_MIDDLEWARE_2` | Kiro 事件摘要 `[{type, index}, ...]` | Anthropic SSE 事件列表 / 非流式响应 JSON |

## 配置示例

```env
# 全部开启（调试所有阶段）
DEBUG_LOG_MIDDLEWARE_0=true
DEBUG_LOG_MIDDLEWARE_1=true
DEBUG_LOG_MIDDLEWARE_2=true

# 只看 Kiro API 交互（最常用）
DEBUG_LOG_MIDDLEWARE_0=false
DEBUG_LOG_MIDDLEWARE_1=true
DEBUG_LOG_MIDDLEWARE_2=true

# 只看格式转换（不关心 Kiro 返回）
DEBUG_LOG_MIDDLEWARE_0=true
DEBUG_LOG_MIDDLEWARE_1=true
DEBUG_LOG_MIDDLEWARE_2=false
```

## input 文件格式

所有 `input` 文件都包含请求头（M0 和 M1 阶段）：

```json
{
  "headers": {
    "host": "localhost:8000",
    "content-type": "application/json",
    "x-api-key": "sk-...",
    "user-agent": "..."
  },
  "body": {
    "model": "claude-sonnet-4-20250514",
    "max_tokens": 8192,
    "messages": [...],
    "stream": true
  }
}
```

M2 阶段的 `input` 是 Kiro 事件摘要（无 headers，因为这是上游返回数据）：

```json
[
  {"type": "assistantResponseEvent", "index": 0},
  {"type": "assistantResponseEvent", "index": 1},
  {"type": "contextUsageEvent", "index": 2}
]
```

## Kiro 事件帧文件

当 `DEBUG_LOG_MIDDLEWARE_2=true` 时，每个 Kiro API 返回的事件帧会单独保存：

```
kiro_anthropic/{dd}/{hh}/{mm}/{ss}/{id}/
├── kiro_event_0000_assistantResponseEvent
├── kiro_event_0001_assistantResponseEvent
├── kiro_event_0002_toolUseEvent
├── kiro_event_0003_contextUsageEvent
└── ...
```

每个文件内容示例：

```json
{
  "type": "assistantResponseEvent",
  "content": "这是 AI 回复的一段文本...",
  "tool_use": null,
  "context_usage": null,
  "error": null,
  "exception": null
}
```

## 源代码位置

| 模块 | 文件 | 说明 |
|------|------|------|
| 日志核心 | `app/services/debug_logger.py` | 所有日志函数定义 |
| M0 调用点 | `app/api/v1/openai/chat_completions.py` | `log_middleware_0()` |
| M1 调用点 | `app/api/v1/anthropic/messages.py`、`chat_completions.py` | `log_middleware_1()` |
| M2 调用点 | `app/api/v1/anthropic/messages.py`、`chat_completions.py` | `log_middleware_2()` |
| Kiro 请求记录 | `app/api/v1/anthropic/messages.py`、`chat_completions.py` | `log_kiro_raw_request()` |
| Kiro 事件记录 | `app/api/v1/anthropic/messages.py`、`chat_completions.py` | `log_kiro_raw_response_chunk()` |
| 配置定义 | `app/core/config.py` | `DEBUG_LOG_DIR`、`DEBUG_LOG_MIDDLEWARE_0/1/2` |

---

## 注意事项

1. **WebSearch 请求**（`/v1/messages` 中检测到 `web_search` 工具）走独立的 MCP 路径，**当前未接入调试日志**。
2. **缓冲模式** `/cc/v1/messages` 端点当前**未接入调试日志**。
3. 所有文件写入通过 `asyncio.create_task` + `run_in_executor` 异步执行，**不阻塞请求处理**。
4. 同一请求的所有阶段共享相同的 `request_id`，可跨目录关联。
